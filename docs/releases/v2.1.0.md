# WG-Easy Port Manager 2.1

Version 2.1 hardens peer self-service management and webhooks, adds a forwarding kill-switch to the web interface and ships `wgpm-agent`, a dependency-free client-side daemon that keeps torrent clients in sync with their forwarded port.

## Highlights

- `wgpm-agent`: stdlib-only Python daemon (qBittorrent / Transmission / Deluge) that consumes signed webhook events, verifies and applies the authoritative lowest forward, reannounces only on real port changes and reconciles by polling.
- Forwarding kill-switch (`forwardingEnabled`) with a fail-closed web UI: disabled controls, amber banner and debounced, rate-limited auto-probes.
- Strict port and rule-id validation on peer routes (hex/float/bool ports and digit-string rule ids are rejected, not coerced).
- Online/reachability window now honors the per-peer `persistentKeepalive` override, in the API and in probes.
- Webhook hardening: SSRF-safe delivery with DNS pinning, bounded transient-only retries, `port.deleted` events, non-global destination enforcement, credential rejection and post-commit emit failures that no longer surface to the client.
- Isolated peer-token rate limits (token floods can no longer evict admin lockout counters), query-string-tolerant auth, malformed-path rejection and self-management re-checked inside the mutation queue (revoke-in-flight closes the TOCTOU).
- UDP-aware probing that still detects missing DNAT rules.

## Upgrade notes

- Webhook targets resolving to private, link-local or metadata address ranges are rejected unless `ALLOW_PRIVATE_WEBHOOK=true` is set.
- To use `wgpm-agent`, follow the setup under `contrib/agent/README.md`; a peer token with `managePorts` scope is required.

Back up `/etc/wireguard` before upgrading. Follow [the VPS deployment guide](../vps-deployment.md) for installation, validation, upgrades and rollback.
