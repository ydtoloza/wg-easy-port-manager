# WG-Easy Port Manager 2.3

Version 2.3 fixes traffic-history persistence across restarts, adds scheduled
automatic state backups with retention, and introduces a consolidated
"all ports" administration view.

## Highlights

- **Traffic statistics now survive restarts** (fix): the sampler always wrote
  `traffic-history.json` into `WG_PATH`, but `load()` was never called on
  boot — every restart silently reset peaks, totals and the 1h/24h/30d
  rollups. The sampler now restores the sidecar before its first sample.
  It also starts at boot (when `UI_TRAFFIC_STATS=true`) instead of only while
  the panel is open, so the long-range rollups stay complete instead of
  growing gaps while nobody is watching.
- **Scheduled automatic backups**: `wg0.json`, `server-settings.json` and
  `webhook.json` are copied into `/etc/wireguard/backups/<timestamp>/` shortly
  after boot and then every interval, keeping the newest N directories
  (default: every 24 hours, keep 7). Pure filesystem, atomic-safe reads, no
  new dependencies; failures are logged and never surface to clients.
  Configure with `WG_BACKUP_ENABLED` (default `true`),
  `WG_BACKUP_INTERVAL_HOURS` (default `24`) and `WG_BACKUP_RETENTION`
  (default `7`).
- **Consolidated "all ports" view**: a collapsible card above the client list
  lists every forwarding rule of every peer in one table with the
  reachability dot, protocol, external/internal ports, peer name and last
  probe time. Includes text search (peer or port), protocol filter and
  probe-status filter (reachable / problems / not probed); clicking a row
  expands and scrolls to the owning peer's port-forwarding section. The
  card's open state persists in `localStorage` like the per-peer sections.

## Upgrade notes

- No required environment changes. Traffic history restored on boot needs no
  configuration; the first restart after upgrading re-seeds the dashboard
  from the existing `traffic-history.json` sidecar.
- Scheduled backups are enabled by default and write into the persistent
  `WG_PATH` volume. Set `WG_BACKUP_ENABLED=false` to opt out, or tune
  `WG_BACKUP_INTERVAL_HOURS` / `WG_BACKUP_RETENTION`.
- RESTORE reminder: the manual backup button in the panel and the scheduled
  backups under `/etc/wireguard/backups/` are plain copies — stop the
  container, replace `wg0.json` (+ `server-settings.json`), start.

Back up `/etc/wireguard` before upgrading. Follow [the VPS deployment guide](../vps-deployment.md) for installation, validation, upgrades and rollback.
