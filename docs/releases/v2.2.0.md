# WG-Easy Port Manager 2.2

Version 2.2 is a web-interface release: a durable notification center, a random
port generator for torrent seeding, per-rule reachability indicators and
persistent port-forwarding sections. It is a frontend-only change — every
backend route, validator and nftables interaction is byte-identical to 2.1.

## Highlights

- **Notification center**: a bell in the top bar keeps the last 100 toast
  events (50 persisted in `localStorage`) with unread badge, relative times,
  a Clear button and a live probe-status section that lists the latest
  verdict per forwarding rule. Probe warnings are no longer lost after the
  toast disappears.
- **Random port generator for seeding**: a dice button next to the external
  port suggests a uniform random free port inside the admin-configured
  forwarding window (`portFwdMin`/`portFwdMax`), never below 1024, skipping
  the Linux ephemeral range (32768-60999, soft exclusion), already-assigned
  ports, the server's own ports and a well-known service blocklist. The
  internal port mirrors the draw unless one was typed. The server still
  re-validates every add authoritatively.
- **Per-rule reachability dots**: green (reachable), amber (open on the
  server but the peer tunnel is down), red (unreachable / DNAT rule missing)
  and gray (not probed yet, UDP or peer offline), driven by the existing
  debounced auto-probes with their 30s per-rule rate limit — no extra
  backend load.
- **Persistent port-forwarding sections**: sections load collapsed by
  default; opened/closed states survive reloads via `localStorage`.
- Housekeeping: probe bookkeeping is pruned when peers or rules are deleted
  (bounded memory), an orphaned duplicate `<path>` in the theme button markup
  was removed, the bell exposes a stable accessible name, and all new UI
  strings ship in English and Spanish (other locales fall back to English).

## Upgrade notes

- No environment variable changes and no configuration migration are
  required. Browser assets are cache-busted (`app.css?v=4`, `app.js?v=7`),
  so clients pick up the new interface on a normal reload.
- The collapsed-by-default behavior replaces the previous auto-expand of
  peers that own forwarding rules; expand once and the preference sticks.
- Known preview limitation (unchanged from 2.1): non-Linux development
  servers still skip port-forward validation; see
  `docs/v2.1-security-constraints.md` Phase 1.

Back up `/etc/wireguard` before upgrading. Follow [the VPS deployment guide](../vps-deployment.md) for installation, validation, upgrades and rollback.
