# v2.1 Security Constraints

Acceptance criteria for the planned v2.1 phases (auto-port assignment, signed
webhooks, per-peer scoped tokens, nat-rules diff endpoint + OpenAPI). These
come from a security pre-mortem against v2.0.0 (`5c3c735`): every item below is
either a verified property of Node/undici/h3 or a verified behavior of the
current code base that the new features would sit directly on top of. A phase
is not done until its items hold — ideally each one lands as a test in the
same PR that introduces the feature.

## Phase 1 — Auto port assignment

- [ ] **Scan + claim must be ONE queued closure.** The free-port scan, the host
  listener probe, and the rule insertion must all happen inside a single
  `__withMutation` operation calling the internal `__addPortForward`. Scanning
  in the route and then calling the public `addPortForward` lets two parallel
  requests claim the same port (and the public wrapper is re-entrancy-guarded
  — it will reject loudly rather than deadlock).
- [ ] **Compute the port range per request from runtime settings**
  (`portFwdMin`/`portFwdMax`), never from the static env snapshot — the
  settings are runtime-mutable and a cached range drifts out of the policy
  window.
- [ ] **Exclude the kernel ephemeral range** (default 32768–60999) or default
  the auto range below it: assigning from 20000–65535 collides with ephemeral
  source binds intermittently.
- [ ] **Host-listener probe must cover TCP and UDP, IPv4 and IPv6.** A `both`
  proto rule DNATs both protocols; probing only TCP silently shadows UDP-only
  daemons (and vice versa).
- [ ] **Skip ports referenced by `WG_PRE_UP`/`WG_POST_UP`** iptables rules.
- [ ] **Strict port validator in `Util.js`** (`Number()` accepts `true`→1,
  `'0x10'`→16, `'5e2'`→500 — verified). Reuse it in every new route.
- [ ] **Return 409 (not 400) on exhaustion/conflict** — conflicts are state,
  not malformed input. Some port-forward conflicts were reclassified to 409 in
  v2.0.x; keep new endpoints consistent.
- [ ] Preview (non-Linux) branch must validate the same way as production so
  the endpoint is testable.

## Phase 2 — Signed webhooks (all verified against Node fetch/undici)

- [ ] **`redirect: 'manual'`** — fetch follows a 30x from a validated
  `https://` URL straight to `http://127.0.0.1` with a 200. Treat any 30x as
  failure, or re-validate the `Location` target with the same rules.
- [ ] **Explicit timeouts** — no fetch timeout exists by default; a slow
  endpoint hangs the delivery until undici's ~300 s headers timeout. Use
  `AbortSignal.timeout(...)` plus dedicated connect/response timeouts.
- [ ] **SSRF gate at CONNECT time, not at configure time.** The daemon runs
  with NET_ADMIN on the host network, so SSRF reaches host loopback, LAN, and
  cloud metadata. Deny private/loopback/link-local/metadata ranges including
  IPv4-mapped and decimal/hex IP encodings; pin the resolved IP with a custom
  undici lookup (DNS rebinding defense). `http://` only behind an explicit
  `ALLOW_INSECURE_WEBHOOK`.
- [ ] **Deliver OUTSIDE the mutation queue** (detached), with the payload
  snapshotted inside the committing operation. A queued delivery head-of-line
  blocks every peer/DNAT mutation behind ~15 s of retries, stalls shutdown,
  and an endpoint that calls back into the API deadlocks the queue.
- [ ] **HMAC secret in a header, never in the URL query** (query survives
  redirects intact — verified), never in argv (command logging), and log at
  most `{host, status, attempt}` — never the secret or full payload.
- [ ] **Timing-safe comparison** (`crypto.timingSafeEqual`) for HMAC and any
  sha256 compare. Never `===` on hex digests. Constant length check first.
- [ ] **Retry caps with jittered backoff, network-layer failures only, and
  the SSRF gate re-checked per attempt** (the resolved IP can change). Three
  eager retries at an internal address is a DoS amplifier from a root process.
- [ ] **Event ID for receiver idempotency** and documented replay window
  guidance (timestamp tolerance ±300 s).
- [ ] Note in docs: outbound proxy env vars are ignored by undici by default.
- [ ] `src/lib/Webhook.test.js` acceptance cases: 30x→internal fails; literal
  private IPs rejected; hung endpoint aborts ≤ ~6 s; key never logged.

## Phase 3 — Per-peer scoped tokens (Bearer)

- [ ] **Exact `Bearer ` prefix parsing.** Today any `Authorization` value is
  consumed as the *admin password*; tokens must not flow into that path, and a
  token equal to the admin password must never authenticate as admin.
- [ ] **Separate `/api/peer/*` handlers with their own gate.** Peer tokens
  must never be OR-ed into the global admin middleware — that is a
  peer→admin escalation. New routes go in a router mounted *after* the admin
  gate with its own token check (the existing authz placement is positional:
  `router1` precedes the gate, so nothing peer-facing may be added there).
- [ ] **Scope exclusion:** token-authenticated requests must never reach
  `/backup`, `/restore`, `server-config`, or client create/delete.
- [ ] **Peer-keyed rate-limit buckets** for token validation and port churn —
  only the shared IP-keyed login limiter exists today; one valid token could
  otherwise churn unlimited DNAT reload cycles.
- [ ] **`timingSafeEqual` for sha256 token-hash compares** (length-safe).
- [ ] **Secrets never echo:** grow `allowedClientKeys`/`SERVER_SETTING_KEYS`
  *and* the response serializers/hidden-key sets in the same PR (restore
  strict-validates unknown client fields; the server-config API filters via
  `serializeServerSettingsPublic`). `/api/session` must stay fixed-shape.
- [ ] **Dedicated serializer for `/api/peer/me`** — `getClient()` returns the
  raw object including `privateKey`/`preSharedKey`; never spread it.
- [ ] **Backups:** decide explicitly whether the API backup dumps token
  hashes; if yes, document that a backup file is bearer of all tokens.
- [ ] Consider out-of-band revocation: manual `wg0.json` edits are inert until
  restart (in-memory cache). Rotation must route through the mutation queue,
  and docs must say so.

## Phase 4 — nat-rules diff endpoint + OpenAPI

- [ ] **Stable rule IDs before the diff endpoint hardcodes positional
  indexes.** Deletion today is positional with no re-validation; two
  concurrent editors can silently delete the wrong rule (v2.0.0 behavior;
  out-of-range now 404s, but indexes still shift under concurrent edits).
- [ ] Do not reuse the `allowedIPs` "no newline" validation pattern anywhere
  near nft command construction — validate CIDR.
- [ ] OpenAPI schema must mark which endpoints are admin-gated vs
  peer-token-gated, and must not advertise `/backup`/`/restore` to peer scope.

## Cross-cutting

- [ ] **Token/secrets at rest as files or 0600-protected fields, not env** —
  the whole `.env` is already readable via `/proc/<pid>/environ` on this
  NET_ADMIN host-network container.
- [ ] **Error contract stays safe:** new sub-500 messages are shown verbatim
  to clients; never put command output or secrets in a thrown message (the
  nft-apply 500 embeds stderr and is only masked by the generic-500 rule).
- [ ] **Test blueprint** (recommended order): HTTP route suite for
  port-forward routes → conflict invariants (409s) → nft payload assertions
  (assert the actual `nft -f -` input) → auto-assign table including
  N-parallel-winner → crash windows incl. partial rollback → api.js↔routes
  error contract → secret non-leak snapshots for every new serializer.
